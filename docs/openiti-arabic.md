# Islamic shelf: Arabic texts from OpenITI

This pass answers the works that earlier passes could only catalogue. Their
English translations were in copyright, out of print, or survived only as bad
OCR; their Arabic originals are public domain. OpenITI publishes
machine-readable Arabic transcriptions, so the library can index and serve
those originals without waiting for a translation.

Twenty-six works are now imported: **2,200 chapters and 330,607 indexed
paragraphs**. The library seeds **1,341 works, 2,243 editions, 1,241,994
passages and 51 local texts**. Islam holds **52 works**.

## 2. Rights

The classical works are public domain. OpenITI's digital transcriptions are
distributed under **CC BY-NC-SA 4.0**, which is a different thing from the
underlying work: attribution and share-alike attach to the transcription, and
commercial reuse is not granted. The library therefore:

- streams the text from GitHub at read time and stores only the catalogue,
  outline and passage index;
- names OpenITI, the repository and the source file on every edition;
- records `cc-by-nc-sa` on the edition, with the underlying work marked public
  domain in its rights note;
- does not relicense the transcription or present it as its own edition.

## 3. How the text is reconstructed

OpenITI files are mARkdown, not HTML. The parser in
[`server/openiti.ts`](../server/openiti.ts) reads:

- `### |` / `### ||` headings; the number of pipes is the heading depth;
- `#` at the start of a paragraph, and `~~` as a continuation of it;
- `PageV01P012` and `ms0001` markers, which are removed;
- conversion prefixes (`AUTO`, `CHECK`, `PARATEXT`) and repeated heading
  markers such as `### || AUTO ### || AUTO فصل`, which are peeled off.

Chapter grouping is declared per work and applied identically at import and at
read time, so the passage index cannot drift from the served text:

- **level** — every heading at or above a chosen depth starts a chapter. Used
  for al-Muwafaqat, al-I'tisam, al-Tawhid, Ibn al-Salah, al-Risala and Riyad
  al-Salihin.
- **pattern** — a heading matching a book or surah pattern starts a chapter and
  deeper headings stay in the text. Used for the manuals (`كتاب`), al-Kashshaf
  (`سورة`) and the Fusus (`فص`).

A work is rejected by the importer if it yields fewer than three chapters,
fewer than 100 paragraphs or 5,000 words, or no Arabic text. It is also
rejected if any chapter is empty. The import manifest
([`data/imports/openiti.json`](../data/imports/openiti.json)) records the
source file, chapter count and paragraph count for every work.

At read time the whole file is fetched once and both the raw text and the
grouped chapters are cached for 30 minutes. Without that cache, moving between
chapters of al-Mabsut would re-download a 13.6 MB file each time.

## 4. Full-text search

A separate index makes these Arabic passages searchable without storing the
work's display text. `bun run index:streams` downloads each file once, maps every
paragraph to the passage index and writes three things to `stream_fts`:

- the normalised Arabic text;
- prefix variants, so `صلاة` also matches `الصلاة` and `وبالصلاة`;
- a short excerpt for result context.

The same normalisation handles Hebrew niqqud and final letters, Greek accents
and final sigma, Arabic-Indic digits and Latin diacritics. Local editions use
the same code path, so a search is not limited to one script. The index is a
derivative: the reader still fetches the chapter from OpenITI, and the passage
shown is the provider's text, not the indexed copy.

## 5. Limits

1. **No English translation.** These editions are Arabic only. The
   availability note says so, and the edition note explains that no
   public-domain English translation was verified.
2. **Chapter outlines are editorial.** They follow the transcription's own
   headings, not a modern critical table of contents. Some works keep the
   author's or editor's front matter as a first chapter; al-Muwafaqat, for
   example, opens with the author's khutba.
3. **Transcription quality varies by edition.** Page markers and conversion
   tags are removed, but OCR slips and editorial numbering remain where they
   are part of the text. The library presents the transcription rather than
   silently correcting it.
4. **Al-Mabsut is large.** Its first read downloads 13.6 MB and may take a few
   seconds; later chapters in the same session come from the cache.
5. **The search index is a separate build step.** `db:reset` rebuilds the
   catalogue but not `stream_fts`; run `bun run index:streams` afterwards. When
   the index is absent the search API says so instead of silently returning
   only local results. The index covers OpenITI as well as the Hadith API,
   AlQuran Cloud, Quran.com tafsir and SuttaCentral shelves; Sefaria remains
   searchable through its live API, and the remaining streamed hosts are
   browsable by work and chapter.
6. **One requested hadith title is still missing.** *Sunan al-Darimi* was not
   in the OpenITI directory inspected for this pass; it is recorded in the
   acquisition register with its source leads. The other titles that earlier
   passes could only catalogue — al-Hidaya, al-Mabsut, al-Mudawwana, al-Mughni,
   al-Risala, Kitab al-Umm, Mafatih al-Ghayb, Asbab al-Nuzul, al-Itqan,
   Musnad Ahmad, Mishkat al-Masabih, Bulugh al-Maram and Nukhbat al-Fikr — are
   now streamed.
7. **No Shia shelf existed before this pass.** Al-Kafi required adding a
   `shia-twelver` school to the corpus vocabulary; the school is used by that
   work and is otherwise unpopulated.
8. **Availability depends on GitHub.** A moved or removed file is reported by
   the reader as a failed fetch; the library does not substitute a local copy.

## 6. Reproduction

```bash
bun run import:openiti            # writes catalogue, streams and manifests
bun run db:reset                  # rebuilds the database
bun run index:streams             # builds streamed-text search index
bunx tsc --noEmit
bun test
bun run build
```

Individual works can be re-imported with `--only=<slug>`, for example
`bun run import:openiti --only=al-hidaya`.
